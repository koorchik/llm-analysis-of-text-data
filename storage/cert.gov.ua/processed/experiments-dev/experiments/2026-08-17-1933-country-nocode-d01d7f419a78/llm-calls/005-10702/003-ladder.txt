--- instructions ---
You derive the GRANULARITY LADDER for one entity category in a knowledge-graph
pipeline. The ladder says how an entity of this category can be named more
coarsely: the same thing with detail dropped, or the wider thing that contains
it. It is a hierarchy over entities only — no facts, no relations.

## Input

category:    <name>
definition:  <one-line definition from the schema>
examples:    <8-20 real surface forms of this category, as they appear in the corpus>

The category may be one you have never seen. Derive the ladder from the
definition and the examples, not from memory of some other schema.

## What a rung is

g0 is the entity exactly as observed, with every discriminating detail intact.
Each higher rung (g1, g2, g3) names either the same referent with detail
dropped, or the wider whole that contains it.

A candidate rung is admitted only if it passes ALL THREE gates:

GATE 1 — SAME CATEGORY. The coarser node must itself be a member of this
category. If the coarser thing belongs to a different category, it is NOT a
rung. Reject it (and record it under "rejected").

GATE 2 — PROJECTION SOUNDNESS. This gate judges the entities themselves — what
they denote and how they contain each other. Do NOT reason through shared
facts ("both were targeted by X", "attributed to Y"): what an entity did or
suffered belongs to the graph's assertional layer, and this ladder is entity
matching only. The coarser node passes if EITHER holds — and it must keep a
named anchor: a thing (the GRU), or a group defined by one (microsoft:*,
anchored to Microsoft). A bare kind ("a unit", "a product") or the category
itself is never a rung:

  a) same referent, wider net — everything the finer name denotes, the coarser
     name also denotes, with detail dropped;
  b) proper part — the finer referent sits inside the coarser one.

Decide between (a) and (b) with the FACT-REWRITE TEST, and record it in the
rung's "foldTest": take a plausible corpus sentence about the finer entity and
rewrite it with the coarser name.

  - The rewrite is the SAME CLAIM stated less precisely -> case (a),
    set "preserving": true.
  - The rewrite is a claim about a DIFFERENT THING -> case (b),
    set "preserving": false.
  - The rewrite is neither -> not a rung at all; reject it.

  "Office 2010 SP2 was exploited" -> "Office 2010 was exploited"
      same claim, service pack blurred            => preserving: true
  "Unit 74455 ran the operation"  -> "the GRU ran the operation"
      now says the whole agency did it            => preserving: false
  "certifiedauth.in was seized"   -> "Domain was seized"
      not a claim about the world                 => not a rung (the category itself)

Tiebreak when the rewrite feels arguable — ask what the coarser node IS. A
COLLECTION of things like the finer one (a product family, microsoft:*, a
sector) folds as "one of them": preserving: true. A THING IN ITS OWN RIGHT
that the finer one belongs to (an agency, a ministry, a parent company) makes
the rewrite change its subject: preserving: false. When still uncertain,
answer preserving: false — a lost fold is safe, a silent subject change is
not.

GATE 3 — NODE ECONOMY. One coarsening, one rung. An anchored group (a star
node like microsoft:*) is admitted ONLY when a pinned reference table computes
membership from the entity's own name or facets — that is what makes it
grouped-by. If membership takes world knowledge, the same coarsening is
already the part-of rung to the anchor itself: "a GRU unit" and "the GRU"
retain exactly the same information (belongs to the GRU), and the agency is a
real referent that reports name, while the star node is synthetic. Emit the
container, never both.

  passes: Microsoft Office -> microsoft:*        (CPE vendor component computes membership)
  fails:  GRU Unit 74455   -> gru:* "a GRU unit" (no table knows Unit 26165 is GRU; this
                                                  coarsening is spelled part-of -> GRU)

## The moves (descriptive) and the flags (load-bearing)

Every admitted rung records the move that produced it — as DESCRIPTION, not as
a decision. Downstream behaviour is decided by two flags, and only one of them
is yours to set:

- "preserving" — YOURS, per rung, from the fact-rewrite test in gate 2. It
  decides whether folding this rung keeps a fact's subject (same thing,
  blurrier name) or widens it (a different, containing thing). When uncertain,
  answer false — the fold stays off, which is the safe failure.
- deterministic — NOT yours. Code sets it by BINDING: it replays your g0
  example through wired reference tables (CPE, the Public Suffix List,
  ISO 3166, …); a rung that binds to no table is treated as defeasible no
  matter which move you named. So do NOT cite standards in your output — your
  job is the honest description, not the citation.

| move            | what it drops                                   | example                              |
|-----------------|-------------------------------------------------|--------------------------------------|
| drop-qualifier  | a version / release / edition / config facet    | Office 2010 -> Microsoft Office      |
| grouped-by      | membership in a set fixed by producer/controller| Microsoft Office -> microsoft:*      |
| part-of         | a proper part -> the whole containing it        | Cyber Command -> Ministry of Defence |
| kind-of         | a specific kind -> the broader kind             | electricity distribution -> energy   |

The moves usually pair with the flag (drop-qualifier and grouped-by rungs are
usually preserving; part-of rungs are widening) — but NOT always: a kind-of
rung is often preserving ("electricity distribution was attacked" IS an
energy-sector attack) even though no table computes it. Answer the flag from
the fact-rewrite test, never from the move name. The single worst error here
is claiming "preserving": true for a rung whose fold changes who a fact is
about — downstream code folds preserving rungs silently once a table confirms
them.

## Hard rules

- NEVER emit the category itself as a rung. "Domain" is not a coarser domain.
- NEVER cross into another category. A vendor rung of Software means "any product
  by that vendor" (still Software), NOT the company (Organization).
- Widening never precedes blurring. Once a rung is "preserving": false, no
  later rung may be "preserving": true — a blur above a subject change would
  blur a different thing. If a ladder seems to need that, the widening rung
  below it is probably not a rung.
- Aliases are NOT rungs. "MS Office" = "Microsoft Office" is the same rung.
- Renames are NOT rungs. "Twitter" -> "X" is one referent over time.
- DO NOT pad. Many categories have no ladder at all: identifiers whose digits ARE
  their identity (CVE-2024-1234, UAC-0002) are depth 1 — emit g0 only. A short
  honest ladder beats an invented one.
- Maximum 4 rungs (g0-g3). If the category seems to need more, emit your best 4
  and say so in "notes".
- If a rung is genuinely contested among sources (rival vendors disagree whether
  one group contains another), still emit it, but set "disputed": true.

## Output

Return ONLY this JSON.

{
  "category": "<name>",
  "ladder": [
    { "g": 0, "alias": "<short noun>", "example": "<from the input examples>" },
    { "g": 1, "alias": "<short noun>", "move": "<one of the four>",
      "example": "<coarser form of the g0 example>",
      "preserving": "<true|false — from the fact-rewrite test>",
      "foldTest": "<one line: '<sentence about the finer>' -> '<rewrite with the coarser>': same claim, less precise | a claim about a different thing>",
      "disputed": false }
  ],
  "rejected": [
    { "candidate": "<coarser thing you considered>", "gate": "1|2|3",
      "reason": "<why it is not a rung, and where it belongs instead>" }
  ],
  "notes": "<anything the schema should know: missing standards, depth pressure>"
}

Rung aliases are local to this category. Where a standard supplies the words,
use them verbatim. Where none does, pick a plain noun — no one will compare it
across categories, the "g" index does that.

The "example" of every rung must be a name the corpus could actually mention —
draw it from the input examples wherever one already sits at that rung. This
ladder feeds an entity-matching graph that holds full mentioned names, so a
rung whose example you had to invent will match nothing; reconsider it. Star
groups (microsoft:*) are the one exception: they are computed fold targets,
never matched against text.
