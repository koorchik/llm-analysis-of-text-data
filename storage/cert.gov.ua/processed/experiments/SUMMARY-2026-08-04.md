## The substantive difference: gemma over-links

| decision | opus-5 | gemma e2b |
|---|---|---|
| link | 92 (2.7%) | 292 (8.7%) |
| mint | 3269 (97.1%) | 2804 (83.5%) |
| defer | 5 (0.1%) | 264 (7.9%) |

gemma issues **3.2× more links** than opus-5 and ends with 3068 canonicals vs 3268. Merge precision
in the dominant stratum collapses to 0.044 — it merges aggressively and wrongly. Its recall is not
much worse (0.600 vs 0.750), so the failure is precision, not coverage.

It also **defers 53× more often**, which is arguably correct behaviour from a weaker model: `defer`
is the protocol's withheld decision (statistical-protocol §5), routing uncertainty to the
consolidator rather than guessing. Note the two arms therefore do not have identical scored
decision counts.

Ladder ensemble validity, 37 firings on gemma: **7× 1/3, 17× 2/3, 13× 3/3** (mean 2.16/3) against
opus-5's uniform 3/3. Consequence: `disputed` is derived from cross-run disagreement, so on the
seven 1/3 firings the flag is computed from a single surviving sample and carries no ensemble
signal.

## Issues found and fixed

1. **`evaluate` silently unscored every v3 registry** (`src/Evaluation/partition.ts`). The
   predicate was pinned to `version === 2`; SKEIN v2 ships registry **v3**, so it fell into the v1
   branch and read the whole file as the category map — `granularityEdges`/`deferQueue` became
   phantom clusters and all real clusters went unscored. First scoring pass reported "33 clusters"
   and undefined merge metrics. Fixed to test for a `categories` map; regression test pins v3.
   **This was a silent wrong answer, not a crash, and it affected both arms.**

2. **`LlmClientBackendOllama` hardcoded `num_ctx: 32768`.** Since the API option overrides the
   Modelfile, `gemma4:e2b-8k` would have run at a 32k window and spilled off the 8 GB card. Now
   derived from the model tag (`-8k` → 8192), with an `OLLAMA_NUM_CTX` override and a log line
   recording the effective window. This is what let the judge model sit 100% on GPU.

3. **`run-card.json` understates cost on a resumed run.** The cost meter is per-process, so the
   resume session overwrote the first session's figures: the card shows $6.85 / 105 calls, the
   true total is **$22.28 / 373 calls**. Deliverable #1 must use the corrected figure. Not fixed in
   code — flagged only.

## Known anomalies (both benign, same root cause)

Document `4905718`'s frozen extraction lists several entities twice. Six duplicate decision points
result; five are idempotent re-mints absorbed by the registry's resolve-first guards. The sixth
(`UAC-0057 (GhostWriter)`) was minted on its first occurrence and linked to `UAC-0057` on the
second — the batched per-document judge decides all mentions against document-start state, but
decisions are applied sequentially.

Consequences, both traced entirely to that one entity:
- cloud `replay --verify`: **1/3366 points differ** (0.03%), exit 1
- cloud viewer self-check: 1 canonical replayed but not on disk → ⚠ banner on that arm

**The final registry is correct**: `UAC-0057` holds aliases `["UAC-0057", "UAC-0057 (GhostWriter)"]`
and no spurious canonical exists. The local arm's replay fidelity is **perfect, 3360/3360**.

Surface coverage was verified as an exact **3354/3354** match against the gold inventory — the
pre-seed was sound and the low merge numbers are not a coverage artifact.

## Threats to validity

- Gold table provisional and unfrozen; no stratum (d).
- The arms sit in **different determinism tiers** (`default-sampling` vs `seeded`) — Anthropic
  silently drops sampling parameters, Ollama accepts a seed. Replicate variance is not comparable.
- Single run per arm; no bootstrap CIs or significance testing (not in the CLI — do not fabricate).
- Granularity edges produced but unscored (no hP/hR).
